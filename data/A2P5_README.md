# A2P5 - A Causality-Guided Program Repair Framework with Counterfactual Regression Verification for AI-Generated Code

**Track:** Track 6  
**Application:** Repair of AI-generated blockchain smart contracts

This dataset is synthetic, generated by gen_author2.py with seed 2051. It must be described as synthetic in any publication.

## Simulated scenario

2,500 bugs in AI-generated smart contracts for a P2P energy-trading platform (energy tokens, trade matching, settlement escrow, meter-oracle adapters, governance). For each bug an AI agent proposes 3-8 candidate patches with different strategies. For each candidate we log patch and causal-impact features and the ground-truth outcome from a held-out behavioural oracle.

## How it was generated

Regression probability = sigmoid(-4.6 + 0.06 slice + 0.55 fan-out + 6 counterfactual divergence + 0.45 state writes + 1.6 modifier change + 0.02 lines - 2.4 test coverage - strategy bonus + bug-type term), standardised to z, + N(0,0.25) noise, then P = sigmoid(-2.6 + 4.5 z). Fix probability depends on strategy, slice size and bug type. 'hidden_regression' = regression AND passes existing tests. 5% noise on measured signals, 1-3% missing, ~0.7% outliers.

## Target / label column(s)

`introduces_regression` (binary, main); `hidden_regression` (hard subset); `fixes_target_bug`. Patch selection = choose candidate with fix=1 and regression=0 per bug_id.

## Suggested experiments

1. Regression prediction: GBM on causal features vs 'passes_existing_tests' baseline; F1, PR-AUC (grouped by bug_id).
2. Patch ranking per bug: top-1 accuracy of choosing a correct, non-regressing patch vs first-passing-patch baseline.
3. Ablation: drop counterfactual_trace_divergence / causal_slice_size and measure loss in hidden-regression recall.
4. Strategy comparison of fix rate and regression rate (with bootstrapped CIs).
